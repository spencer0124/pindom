# 장소 누끼로 함께 촬영하기

> 관데공 장소를 찾고, 투명 PNG 누끼와 사진을 합쳐 티켓으로 남기는 사용자·팀 가이드입니다.

## 준비하기

누끼 기능과 카메라 테스트를 지원하는 앱으로 업데이트하고 카메라 권한을 허용합니다. 마로니에공원은 등록 핀 기준 50m 내 GPS 인증과 위치 권한이 필요합니다. 나머지 관데공 장소의 카메라 테스트에는 위치 권한이 필요하지 않습니다. 지도에서 최애를 **관데공**으로 선택한 뒤 원하는 장소를 엽니다. 사진을 불러오려면 인터넷 연결이 필요합니다. 기본사진은 제공 원본의 내용과 방향을 유지한 앱 표시용 JPEG를 사용해 다운로드 용량을 줄입니다.

지도 핀은 API로 확인한 **장소의 대표 좌표**입니다. 제공 사진을 찍은 정확한 위치는 아니므로 실제 촬영 지점과 다를 수 있습니다. 마로니에공원을 제외한 장소는 **위치 제한 해제 · 카메라 테스트** 상태이므로 장소와의 거리, 위치 정확도, 이동속도와 관계없이 촬영할 수 있습니다. 이 상태는 사용자가 복구를 요청할 때까지 유지되며 자동 종료일은 없습니다. 로그인·이메일 인증, 이용 한도와 같은 장소의 티켓 발행 대기 기간은 그대로 적용됩니다.

## 촬영하고 티켓 만들기

1. 장소 상세에서 배경 사진과 제공자 영문 이니셜, 사진 출처를 확인합니다.
2. 마로니에공원에서는 GPS 인증 후 촬영합니다. 다른 장소는 **카메라 테스트**를 누른 뒤 **카메라 열기**를 누릅니다. 서버가 테스트 권한을 확인하면 촬영 화면으로 이동합니다.
3. 화면에 나타난 누끼를 드래그해 옮깁니다. **누끼 크기** 슬라이더로 크기를 조절하고, **좌우 반전**으로 방향을 바꿉니다.
4. **인물 켜짐 / 인물 꺼짐**으로 표시 여부를 선택합니다. **초기화**는 누끼의 위치·크기·방향을 처음 상태로 돌립니다.
5. 셔터를 누릅니다. 실제 카메라 모드에서는 촬영한 사진을 고정한 뒤, 배치한 PNG 누끼를 합쳐 한 장의 사진으로 저장합니다.
6. 사진 편집 화면에서 결과를 확인하고 필요한 편집을 합니다. **다음**을 눌러 공개 범위를 선택한 뒤 기존 티켓 발행 흐름을 완료합니다.

테스트 중 사진과 티켓에는 **TEST**가 표시됩니다. GPS 방문 인증 완료를 뜻하지 않습니다. 위치 제한을 풀어도 실제 기기의 카메라는 그대로 사용하며, 개발용 샘플 사진 모드로 전환하지 않습니다.

**셀카로 전환**을 누르면 전면 카메라로, **후면으로 전환**을 누르면 후면 카메라로 돌아옵니다. 셀카는 거울 방향으로 촬영하며 인물의 배치와 반전 설정은 그대로 유지합니다. 일반·광각 선택은 후면 카메라에서 제공합니다. 촬영 중에는 전환할 수 없습니다. 전면·후면 카메라가 하나뿐인 Mac에서는 별도 화각 전환이 제한될 수 있습니다. 실제 전면 카메라와 저장 방향은 새 빌드에서 실기기 확인이 필요합니다.

누끼는 촬영할 때 사진에 합쳐집니다. 편집 화면에서 누끼만 다시 옮길 수는 없으므로 구도를 바꾸려면 **재촬영**을 누릅니다. 누끼를 끈 채 촬영하면 실제 사진만 편집 화면으로 전달됩니다.

누끼를 꺼도 사진 프레임 크기는 유지됩니다. 크기 조절부는 자리를 유지한 채 비활성화되고, 다시 켜면 기존 위치·크기·반전을 이어 사용합니다. **좌우 반전**은 누끼 인물을 뒤집는 기능이며 카메라 영상 자체를 뒤집지는 않습니다.

Mac에서 iOS 앱을 실행할 때는 Pindom 창을 클릭해 활성화합니다. 다른 앱으로 전환하면 라이브 카메라와 촬영은 잠시 멈추지만 누끼와 조작부는 유지되며 안내를 표시합니다. 창을 다시 활성화하면 실제 카메라를 다시 엽니다. 카메라의 일시 중지를 누끼 이미지 로딩 실패와 구분합니다.

## 등록 사진 확인하기

현재 탐색 목록은 관데공 등록 장소를 유지합니다. 기존 테스트 장소와 해당 코스는 탐색·검색·추천에서 숨기며, 기존 티켓과 장소 기록은 보존합니다. 현재 장소·누끼 목록과 복구 후 적용할 반경의 원본은 [관데공 카탈로그](../../src/mocks/gwandegong-catalog.json)에서 확인합니다.

| 항목 | 표시와 처리 |
| --- | --- |
| 제공자 | 모든 이름은 `YHJ`, `JSY`, `LJW`, `KMJ`처럼 영문 이니셜로만 표시합니다. 실명을 추가하지 않습니다. |
| 몰리또 대학로점 | 추가 제공된 원본사진을 기본사진으로 표시합니다. 인물 누끼는 유지합니다. |
| 아르떼뮤지엄 부산 | 추가 제공된 원본사진으로 교체했습니다. 기존 외관 대표사진 출처 표시는 제거했습니다. |

새 앱 빌드의 장소 기본사진에는 로딩 안내와 실패 시 재시도 버튼을 표시합니다. 표시용 사진 교체는 서버에서 반영되므로 기존 앱에도 재조회로 적용됩니다.

## 반영 범위와 문제 해결

| 상황 | 확인할 내용 |
| --- | --- |
| 기존 앱에 새 장소가 보이지 않음 | 지도·최애 목록에서 데이터를 다시 불러오거나 앱을 다시 엽니다. 백엔드에 등록한 핀·기본 장소 사진은 데이터 재조회로 반영됩니다. |
| 장소는 보이는데 누끼 조작부가 없음 | 누끼 촬영 기능이 포함된 앱으로 업데이트합니다. 데이터 재조회만으로 이전 앱에 새 촬영 기능이 생기지는 않습니다. |
| 누끼를 불러오는 중이거나 로딩 실패 | 인터넷 연결을 확인하고 다시 시도합니다. 누끼 없이 촬영하려면 **인물 꺼짐**으로 전환합니다. |
| 카메라가 열리지 않음 | 카메라 테스트가 활성 상태인지 확인하고 기기 설정에서 카메라 권한을 허용한 뒤 다시 시도합니다. 로그인·이메일 인증·이용 한도 오류는 화면 안내를 따릅니다. |
| **샘플 사진으로 촬영 연습 중** 표시 | 개발용 모의 촬영입니다. 장소 사진으로 편집 흐름을 확인할 수 있지만 실제 카메라 촬영 결과는 아닙니다. |

장소 보관·테스트 허용 상태는 서버 데이터이므로 다시 불러오면 반영됩니다. GPS 권한 없이 여는 버튼과 **TEST** 표시는 앱 코드 변경입니다. 개발 빌드는 JavaScript 새로고침으로 확인할 수 있고, 배포된 앱에는 새 앱 빌드·설치가 필요합니다. 아이콘·스플래시를 함께 바꾸는 경우 네이티브 리소스도 다시 빌드해야 합니다.

위치 제한을 복구하려면 서버의 해당 장소 `cameraTestEnabled`를 끕니다. 앱을 다시 불러오면 기존 GPS 인증 흐름이 돌아오며, 아직 쓰지 않은 테스트 권한으로도 티켓을 새로 발행할 수 없습니다. 이미 발행한 테스트 티켓의 표시는 유지됩니다.

## 팀 검증 상태

누끼 촬영 기능의 2026-09-20 검증에서 타입 검사·린트·테스트와 iOS·Android Hermes 번들 내보내기를 통과했습니다. iPhone 17 Pro Simulator에서 제공 배경과 투명 누끼의 표시, 접근성 동작을 통한 위치·크기 조절, 좌우 반전·켜기/끄기, 1200×1600 합성 JPEG 저장, 편집 화면과 티켓 미리보기까지의 전달, 비공개 모의 티켓 발행을 확인했습니다. iOS 캡처 경로를 `file://` URL로 정규화해 편집기에서 읽도록 처리했습니다.

이 Simulator 기록은 기존 누끼 촬영 기능의 검증입니다. 이번 위치 제한 해제와 보관 필터 변경은 타입 검사·린트와 자동 회귀 검사를 통과했습니다. GPS 미요청, 서버 거부 시 촬영 차단, 설정 복구, 기존 기록 보존과 TEST 전달을 검사했으며, 새 화면 흐름의 Simulator·실기기 검증은 별도로 필요합니다.

시뮬레이터 검증은 개발 모의 촬영입니다. 실제 기기의 카메라 촬영, 손가락 드래그, 렌즈별 구도 유지와 Android 기기에서의 합성 저장은 별도 확인이 필요합니다. 검증 화면과 합성 예시는 [검증 자료](../../.impeccable/review/cutout/)에 있습니다.

Mac TestFlight 앱에서 창 비활성화 시 촬영 영역 전체가 사라지는 현상을 확인했고, 앱을 전면으로 연 뒤 실제 MacBook 카메라·명륜당 누끼 표시와 좌우 반전이 동작하는 것도 확인했습니다. 따라서 카메라는 보이지만 누끼만 누락된 사용자 증상을 창 활성화 하나로 단정하지 않습니다. 수정에서는 사진 프레임의 측정 크기를 누끼에 바로 전달하고 표시 순서를 고정하며, 렌즈 선택으로 카메라를 재생성하지 않습니다. 비활성 창에서도 누끼가 유지되고 실제 카메라만 정지하는 렌더링 경로는 자동 회귀 검사로 확인합니다. 현재 설치된 TestFlight 앱에는 아직 이 수정이 들어 있지 않으므로 새 빌드에서 Mac 카메라·토글·반전·촬영 결과를 다시 확인해야 합니다.

수정 코드의 Simulator에서는 명륜당 누끼를 끄고 다시 켜도 프레임의 크기·구도가 같고, 좌우 반전·크기·위치 조절이 반영된 합성 사진이 편집 화면으로 전달되는 것을 확인했습니다. 카메라 정지 중 누끼 유지와 측정 크기 즉시 전달은 컴포넌트 회귀 검사로 확인했으며 타입 검사·린트·전체 테스트와 iOS·Android Hermes 내보내기를 통과했습니다.

화면은 기존 [디자인 기준](../../DESIGN.md)의 연분홍·흰 표면, 로즈 액션, 공통 버튼·슬라이더와 글자 스타일을 이어 사용합니다. 이번 기능은 장소 상세와 촬영 흐름의 확장이며 디자인 정체성을 바꾸지 않습니다.
